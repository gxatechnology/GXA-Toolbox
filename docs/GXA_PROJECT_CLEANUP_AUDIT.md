# GXA Toolbox Project Cleanup Audit

Date: 2026-10-27
Scope: local working tree, Git index/history at `fa0d7691c54d5cf50b28e05da46b9b139188968f`, generated `dist/`, and non-mutating live URL probes.
Mode: audit only. No file was deleted, moved, committed, pushed, deployed, or written to production.

## Executive decision

The project is structurally safe to keep working in, but it is **not safe to perform a broad cleanup**. The current tree contains a large, interdependent release in progress (49 modified, 2 deleted, and 27 untracked paths before this report). Most apparent duplication is intentional source/build/runtime duplication. Only generated caches and two superseded hashed Background Remover bundles qualify as high-confidence cleanup items.

The production publish boundary is materially cleaner than the source tree: `dist/` contains 245 files (164,141,763 bytes), including 126 HTML documents, and contains **zero** PHP, SQL, source-map, env, TypeScript, JSX, PowerShell, or log files. The generator therefore prevents the legacy PHP compatibility tree, tests, docs, migrations, and developer configuration from reaching Netlify's publish directory.

## Duplicate and size findings

Byte-identical production duplicates total 28,830,038 bytes across three pairs: model configuration (818 bytes), `u2netp-web.onnx` (4,574,267 bytes), and asyncify WASM (24,254,953 bytes). These are **not approved deletions** because the main site engine and React Background Remover use different URL roots and runtime-loading strategies.

Safe immediate Git/repository reduction is only 421,994 bytes from the two already-superseded tracked Background Remover bundles. Safe immediate production reduction is 0 bytes because those obsolete bundles are already absent from the current `dist/`.

Potential production reduction after a dedicated runtime-consolidation project is approximately 33.4 MB (the duplicate model/WASM plus the retained incompatible original model), but it requires direct Background Remover tests across WASM fallbacks, mobile browsers, CSP, offline/cache behavior, and deployment headers.

## Security exposure audit

- No tracked `.env` file was found.
- The prior release scan of 512 current source files found no private key, JWT, GitHub token, Google API key, PostgreSQL URL, or PEM body.
- `dist/` contains no server source, SQL, source maps, logs, env files, or developer scripts.
- Common sensitive live URL probes are non-public as listed above.
- Third-party advertising, GTM, GA4, AdSense configuration and public publisher IDs are intentionally public identifiers, not secrets; server credentials must remain Netlify environment variables.
- Dependency audit remains separate from cleanup: 0 critical, 6 high and 2 moderate advisories were previously observed. Broad forced upgrades are not approved in this cleanup audit.

## SEO and routing protection

- `robots.txt`, `sitemap.xml`, canonical route generation, 404 handling and direct routes were verified by the production build.
- Sitemap contains 109 unique HTTPS URLs under `gxatoolbox.in` with no query strings or fragments.
- Arbitrary invalid live routes return 404 rather than a soft-200 page.
- Do not delete the 14 noindex/ad-free tool routes merely because they are excluded from indexing; they remain registered functionality.
- Do not remove generated route directories independently. Change the central registry/publication policy and regenerate only after route-level review.

## Recommended cleanup sequence

1. Finish and approve the current feature release; do not intermingle cleanup with the 78-path working-tree change set.
2. Commit the two superseded hashed bundle deletions together with their replacement hashed bundles and updated Background Remover index.
3. Keep `dist/`, `node_modules/`, `test-results/`, and `.netlify/` ignored. Locally remove only reproducible caches after release evidence is archived.
4. Open a separate PHP-retirement decision. If PHP hosting compatibility is no longer required, archive the legacy PHP tree in a tagged release before deleting it from the main branch.
5. Open a separate Background Remover asset-consolidation task; measure real requests before removing any ONNX/WASM variant.
6. Obtain the Search Console 126-URL export and reconcile each URL against the 109 sitemap URLs, redirects, canonicals and noindex policy.
7. Run lint, tests, production build and browser suites after any approved cleanup batch.

## Validation status

The current code state (before adding these documentation files) passed `npm run lint`, `npm test`, `npm run build`, and `git diff --check`. The production build completed with exit code 0. Tool-route, engine, database-isolation, SEO, ad-layout, responsive, ratings, and admin browser/contract suites were executed in the preceding release verification. This audit made no runtime-code changes.

## Final recommendation

**Cleanup GO:** generated local caches and the two superseded hashed bundles only.
**Cleanup NO-GO:** broad deletion of legacy PHP, models, WASM variants, migrations, tests, generated route sources, or current untracked feature files.
**Deployment status:** this audit does not authorize deployment. The repository remains intentionally uncommitted and undeployed.
