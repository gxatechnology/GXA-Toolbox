# GXA Toolbox Phase 1 Test Report

## Automated checks

- JavaScript syntax validation covers the application, preview runtime, shared studio shell, repository audit, fixture generator, and output-validation test.
- The repository audit verifies 91 unique registered tools, preserved static/production entry wiring, Phase 1 studio integration, crop/page operations, generated-output validation, dependency states, and absence of simulated-success patterns.
- Binary fixture tests verify PNG signatures and dimensions, JPEG and WebP signatures, PDF headers/trailers, and PDF page counts.
- The production `build` script runs lint plus both test suites because this application is an unbundled PHP/static deployment.

## Safe fixtures

Generated by `tests/fixtures/generate-fixtures.mjs`:

- Images: landscape PNG, portrait PNG, transparent PNG, large-resolution PNG, small PNG, JPEG, WebP, corrupt PNG, unsupported file.
- PDFs: one page, five pages, text, scanned-style, mixed-content, rotated page, 80-page large PDF, corrupt PDF.
- A note replaces an encrypted fixture because generating a pretend encrypted PDF would violate the product's no-fake-processing rule.

Fixtures contain only deterministic shapes/text generated for GXA Toolbox testing.

## Output validation boundaries

- Image output is decoded with `createImageBitmap` where available and must have non-zero dimensions.
- PDF output must contain valid PDF header/trailer signatures before success.
- ZIP output must parse with CRC checks and contain at least one entry.
- SVG output must begin with an SVG root.
- Crop Image additionally decodes its result and checks final dimensions before presenting download.

## Responsive matrix

Live in-app browser checks exercised 1920, 1366, 1024, 768, 430, 390, 375, and 320 CSS-pixel widths. Each viewport reported `scrollWidth <= clientWidth`; no horizontal page overflow was introduced. The mode rail changes from vertical to horizontal at the planned breakpoint, and the settings drawer is available at 430px and below. At 320px the drawer transferred focus to its labelled close control, updated `aria-expanded`, closed successfully, and left the page overflow-free. The desktop close control remains hidden. Dark mode was toggled live on the 320px layout and retained the same overflow result.

## Live processing checks

- Compress Image: a 1200 × 800 fixture was rotated 90 degrees, adjusted, watermarked, and encoded to a real 800 × 1200 blob. The measured result was 12.73 KB versus 78.09 KB input and completed in 157 ms on the verification machine.
- Crop Image: a 512 × 512 transparent PNG used the 4:5 preset plus rotation and produced a decoded 336 × 420 PNG. Undo became available after the edit and the result view reported actual dimensions and blob size.
- Crop PDF: the five-page fixture rendered five lazy PDF.js thumbnails and the manual crop overlay. Applying 50-point margins to odd pages produced a validated PDF blob of 1.23 KB from a 1.70 KB input in 38 ms on the verification machine.

Timing and byte-size values are observations from this verification run, not product performance guarantees.

## Accessibility checks

- Existing skip navigation and semantic landmarks remain.
- Studio mode rails are labelled navigation regions with current-page state.
- Settings drawers expose `aria-controls`, `aria-expanded`, Escape close, focus transfer, a labelled in-drawer close control, and a labelled backdrop.
- Page thumbnails expose pressed/current state.
- Crop canvases retain numeric controls for precise non-pointer operation.
- Status and errors use live regions.
- Focus-visible and reduced-motion rules are present.
