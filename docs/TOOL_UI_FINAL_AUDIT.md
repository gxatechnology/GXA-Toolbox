# Final tool UI audit

95 routes × 10 widths before and after (950 observations each). All routes were directly loaded at 320px; representative routes were also refreshed at 390px. Widths: 320, 360, 390, 430, 768, 1024, 1280, 1440, 1600, 1920. Browser DOM/geometry review is not equivalent to manually inspecting every screenshot or processing every tool. Ads were blocked here; filled-ad safety is covered separately.

## Root causes

- Shared mobile CSS assigned full width to heading actions, pushing Favorite below the title.
- Three specialized main-app headers omitted category/icon/Favorite and used shortened breadcrumbs.
- Four engines rendered a redundant initial prompt in a live status area; reset repeated it in three engines. Only initial/reset copy was changed; progress/errors remain.
- Crop empty-state styles hardcoded a dark surface and pale text, ignoring the light theme.
- Empty input widths/heights and heading spacing used scattered constants.
- Background Remover retained a standalone oversized heading, absent breadcrumb and nonstandard upload label. React processing architecture is unchanged. Its favorite control remains absent rather than inventing a second persistence system.
