## I. Twenty FAQs

1. **How many tools are available?** The audited registry contains 92 tools in six categories.
2. **Do all 92 tools currently work?** Ninety-one have working client-side paths; PPT to PDF is deliberately blocked because no faithful renderer is installed.
3. **Are my files uploaded?** The audited file-processing paths keep file bytes in the browser; identity/history metadata uses hosted services.
4. **Does the site work offline?** No full offline claim is supported; pages and some engines/assets require network loading and there is no Service Worker.
5. **Which tools use WebAssembly?** Background Remover and qpdf-based Protect/Unlock are WASM-primary; OCR also uses a WASM core in its Worker.
6. **Does Background Remover use AI?** Yes, a local ONNX foreground-segmentation model plus manual mask refinement.
7. **Can I edit the PowerPoint produced from a PDF?** The current PDF-to-PPT path creates one rendered page image per slide, not editable reconstruction.
8. **Does Word to PDF preserve Word pagination?** No; it creates a readable semantic/reflowed PDF within documented limits.
9. **Does Sign PDF create a certificate signature?** No; it places a visible signature appearance.
10. **Are exchange rates live?** No; Currency Converter uses a rate supplied by the user.
11. **Can scanned PDFs be converted to text?** OCR PDF supports bounded English OCR and downloads OCR assets when needed.
12. **Why can browser tools have limits?** Decoded images, PDF canvases, archives and WASM files can use much more memory than their compressed input size.
13. **Can I use GXA Toolbox on mobile?** The product has dedicated responsive navigation/workspaces; heavy workflows still depend on device capability and memory.
14. **Can I save history?** Signed-in users can store job/history metadata; uploaded file blob storage was not found.
15. **Is an account required?** Public tools are accessible without an account; dashboard/profile/history features use Identity.
16. **Which browsers can read QR/barcodes?** Reading currently depends on the browser's BarcodeDetector capability.
17. **Can PDF compression reduce image quality/size?** Optimize PDF currently restructures the PDF losslessly; it does not downsample images and may not reduce size.
18. **What languages does OCR support in the UI?** The audited OCR flows are configured around English; do not advertise multilingual OCR yet.
19. **Are analytics or ads present?** GTM and the AdSense site loader are installed on generated public pages.
20. **Who makes GXA Toolbox?** GXA Toolbox is a product of GXA Technologies.

### 200 words

GXA Toolbox is GXA Technologies' multi-utility web product for common file, data and calculation work. The current source registry contains 92 tools in six categories: 22 PDF tools, five image tools, 21 converters, two ZIP tools, 27 developer/utility tools and 15 calculators. Users can merge and organize PDFs, crop and compress images, generate QR codes, inspect archives, format JSON, calculate EMI and much more from one searchable, responsive interface.

The product is browser-first by design. Ninety-one working workflows perform their primary processing in browser code, a Web Worker or local WebAssembly. Protect and Unlock PDF use qpdf WASM; Image/PDF OCR use Tesseract workers; Background Remover uses ONNX Runtime Web and a local segmentation model. Some engines or language/model assets still need to download, so GXA Toolbox does not make a blanket offline claim.

Static route generation gives each public tool a direct URL, tailored metadata, canonical identity and structured data. Netlify Identity provides optional sign-up, sign-in, recovery and dashboard/profile/history metadata, backed by Functions and PostgreSQL. The product openly distinguishes faithful operations from browser-limited representations—for example, PDF-to-PPT makes page-image slides and visible PDF signatures are not certificate signatures. One registered tool, PPT-to-PDF, remains deliberately blocked pending a faithful renderer.

## Technical elevator pitch

GXA Toolbox is a registry-driven static/browser application deployed from Netlify `dist/`, with 99 public route shells, a vanilla-JavaScript core, a dedicated React/Vite ONNX editor, Worker/WASM processing, Netlify Identity, 19 Function modules and six PostgreSQL tables. Its 92-route matrix includes 59 fully working browser tools, three WASM-primary tools, 29 browser-limited tools and one explicit blocker.
